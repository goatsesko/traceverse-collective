22. PDF / DOCUMENT PROCESSING
==================================================

When a creator uploads a PDF:

1. Securely store the original file.

2. Extract text.

3. Extract images.

4. Detect chapters.

5. Detect headings.

6. Detect paragraphs.

7. Detect tables.

8. Detect illustrations.

9. Detect footnotes where possible.

10. Generate metadata.

11. Generate a structured TraceVerse book.

12. Generate responsive HTML chapters.

13. Store book structure in JSON.

14. Generate a mobile preview.

15. Notify the creator when processing is complete.

Processing must happen asynchronously.

Do not force the creator to stare at a loading screen.

Show:

"Your book is being prepared."

"Feel free to continue browsing TraceVerse."

Notify the creator when ready.

==================================================
23. TRACEVERSE NATIVE BOOK FORMAT
==================================================

The original uploaded PDF remains safely stored.

But readers should read the native TraceVerse version.

Use:

JSON for structured book metadata/content references.

HTML for responsive chapter content.

Images stored separately.

Audio stored separately.

Example conceptual structure:

book.json

{
  "title": "...",
  "author": "...",
  "cover": "...",
  "genre": "...",
  "language": "...",
  "ageRating": "...",
  "chapters": [
    {
      "id": "...",
      "title": "Chapter One",
      "contentUrl": "..."
    }
  ]
}

Chapter HTML:

<h1>Chapter One</h1>

<p>...</p>

<p>...</p>

<img src="...">

The exact production schema should be normalized and versioned.

Never couple the reader directly to raw PDF files.
